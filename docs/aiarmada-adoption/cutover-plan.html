Rules For Parallel Execution

RuleDetail
1. No file overlapTwo WUs must never modify the same file. If they need the same file, run them sequentially. The caller files in WU3-WU10 are model-specific — SavedSearch callers don't touch EventCheckin callers, etc. Verify with grep before starting.
2. Claim before workUpdate the tracker table above with your name and set status to "In Progress" before touching any files. Commit with the WU number in the message: WU3: collapse SavedSearch wrapper — caller migration.
3. Verify before unclaimRun the WU's verify tests. If they pass, update the tracker to "Done" and mark the checkboxes. If they fail, fix before moving on.
4. Phase gatingAll Phase 1 work units (WU1, WU2, WU13, WU14) must be Done before starting Phase 2 (WU3-WU10) — but Phase 1 units can all run in parallel.
5. No legacy bridgesDo not add backward-compat aliases or fallbacks. If a caller needs a feature from the package that the package doesn't provide, extend the package model with a trait — do not create a wrapper model that mirrors legacy naming.
6. Package firstAlways import from AIArmada\* directly. App\Models is for traits/concerns only. The goal is zero wrapper models by Phase 5.
