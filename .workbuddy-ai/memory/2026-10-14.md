# 2026-10-14

## Fixed PSR-4 autoload warnings from inline test helper classes

`composer install` / `composer dump-autoload -o` reported 9 classes in `tests/` that did not
comply with PSR-4 (they were declared inside Pest test files in the global namespace, so the
file name could never match the class name).

Extracted every one into its own PSR-4 file (namespace = directory namespace), removed the
inline declarations, and imported them from the test files:

- `tests/Feature/ShareCards/Wp3ScThrowingPresenter.php`, `Wp3ScThrowingRenderer.php`
  → `Tests\Feature\ShareCards` (used by `Wp3ShareCardTest.php`)
- `tests/Feature/ShareTracking/Wp2ThrowingFraudRule.php`, `Wp2LifecycleThrowingRule.php`
  → `Tests\Feature\ShareTracking` (used by `Wp2RealDriverOutcomeTest.php`, `Wp2LifecycleTest.php`)
- `tests/Feature/Rewards/Host/DigestMailThrowOnceRecorder.php`,
  `DigestMailAcceptThenThrowTransport.php`, `DigestMailLogicThrowTransport.php`,
  `DigestMailAcceptThenThrowLogicTransport.php`, `ResolveCmdThrowTransport.php`
  → `Tests\Feature\Rewards\Host` (used by `RewardDigestMailAmbiguityTest.php`,
  `RewardDigestMailResolveCommandTest.php`)

Also dropped imports that became unused after the extraction, and ran Pint (fixed one
`ordered_imports` issue).

### Verification

- `composer dump-autoload -o` → no "does not comply with psr-4" / "Skipping" lines.
- Baseline vs after, 4 affected non-real-driver test files: **27 failed, 43 passed
  (474 assertions)** both before and after — no regression.
- `RewardDigestMailAmbiguityTest` (10 failures) and `Wp2LifecycleTest` (17 failures) were
  already failing on the baseline commit; `Wp2RealDriverOutcomeTest` fails only because the
  isolated PostgreSQL fixture on 127.0.0.1:45432 is not running (environmental).

### Gotcha worth remembering

`ResolveCmdThrowTransport` was extracted but the `use Tests\Feature\Rewards\Host\...` import was
missed on the first pass → "Class not found" at runtime, which `php -l` and
`composer dump-autoload` do **not** catch. Always grep each moved class name across `tests/`
after a move, and re-run the owning test file.

## Investigated: "Package symplify/rule-doc-generator-contracts is abandoned"

Just noise — do **not** try to "fix" it.

- It is `packages-dev` only (never installed by `composer install --no-dev`), pulled in by
  `driftingly/rector-larabel` `require: symplify/rule-doc-generator-contracts ^11.2`.
- It is genuinely used at runtime: ~every `RectorLaravel\...` rule
  (`Symplify\RuleDocGenerator\Contract\DocumentedRuleInterface`, `ValueObject\RuleDefinition`,
  `ValueObject\CodeSample\CodeSample`) extends/implements it. `RectorLaravel\AbstractRector`
  itself implements `DocumentedRuleInterface`.
- Latest `driftingly/rector-larabel` is 2.6.2 (2026-08-29) and **still** requires it, so
  upgrading does not drop the dep. No suggested replacement upstream.
- You cannot `replace` it or remove it — that breaks every rector-larabel rule.
- Composer has no per-package suppression; only `composer install -q` (hides all output).
- Verified `app/` and `tests/` reference nothing from `Symplify\` — it is purely rector tooling.

Leaving as-is is correct: keeping `LaravelSetList::LARAVEL_130` in `rector.php` depends on it.
