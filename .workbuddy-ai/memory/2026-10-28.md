## Added a live Google Map + navigation to the Lokasi card

`Address` (aiarmada/addressing) carries `latitude`, `longitude`, `google_place_id`,
`google_maps_url`, `waze_url`, `navigation_links`, and there is a
`BuildAddressNavigationLinksAction` — but it only builds *search* URLs, not directions.

The seeded addresses have real coordinates but no `google_place_id` / `google_maps_url`,
so the embed is built from coordinates:

- embed: `https://www.google.com/maps?q={lat},{lng}&z=16&hl={locale}&output=embed`
  (keyless; Google 301s it to the canonical `/maps/embed?pb=!1m3...` form, which is fine
  inside an iframe — do not hand-build the `pb=` protobuf)
- navigation: `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}`

Falls back to the formatted address query when there are no coordinates, and the whole
card is skipped when there is neither. `GOOGLE_MAPS_API_KEY` exists in `.env` but is wired
into nothing — the keyless embed was used instead so nothing depends on an unverified key.

Screenshot gotcha: a `loading="lazy"` iframe is missed by full-page captures that scroll
too fast — the map looked "missing" on mobile until it was scrolled into view and given
~5s. Always confirm a lazy iframe with a viewport screenshot before debugging CSS.

## Merged Penganjur into Lokasi (they are the same place)

`Event::resolvedLocationAddress()` (app/Models/Event.php:1856) falls back
default_venue → primary location venue → **institution**. So for a majlis with no explicit
venue, the organiser's own address *is* the location, and two cards printed the same name
twice.

Detection: compare the rendered address id against the organiser's primary address id
(`Institution::primaryAddress()` from `HasAddresses`). Not `locationable_type` — this
event's `event_locations` row has a `venue_space_id` but no `venue_id` and no address of
its own, so the address only shows up via the institution fallback. Comparing ids is the
only reliable signal.

Result: one card — eyebrow `Penganjur & lokasi`, h2 = institution name (linked), gold
line = the hall (`venue_space`), hairline, address, Navigasi, "Buka dalam Google Maps".
When the venue *is* distinct, the eyebrow stays `Lokasi` and an inline
"Dianjurkan oleh {organizer}" link replaces the old card. `@elseif($organizer)` keeps the
standalone organiser card for events with no usable place data.


## Occurrence images: supported size, and the morph-alias trap

**What the events package actually supports for an occurrence image** (verified at runtime,
`config('events.media.profiles.occurrence')`, defined in
`vendor/aiarmada/events/config/events.php` ~line 180):

- collections: **`cover` only** — `image/jpeg|png|webp`, `single_file: true`, `responsive: true`
- conversions: `thumb` → **1920x1080 (16:9)**, `fit: max` (never upscales), `sharpen 10`, `format webp`

So an occurrence gets **one** photo, 16:9. The event profile additionally has `poster`
(→ `poster_thumb` 1080x1440) and `gallery` (→ `gallery_thumb` 1080x1080).
`$occurrence->getFirstMedia('poster')` in the old view was always null — occurrences have no
`poster` collection.

**The trap that cost an hour:** `App\Models\Event` and `AIArmada\Events\Models\Event` resolve
to *different morph aliases* (`event` vs `package_event`). Media attached through the package
model is invisible to `$appEvent->getMedia('gallery')`, and `media-library:regenerate` silently
writes the conversion into a different directory tree. Always attach through the model class the
app actually queries (`App\Models\Event`). Occurrences are fine — there is no App subclass, so
`event_occurrence` is correct.

**Owner context:** any query/attach on these models outside an HTTP request throws
`NoCurrentOwnerException`. Wrap the whole script in
`OwnerContext::withOwner(null, fn () => ...)` (explicit global) — that is the documented
escape hatch, not `withoutGlobalScopes()` alone (which is also needed to *find* the row).

**Scratch-script gotcha:** a file `require`d by `php artisan tinker --execute` must start with
`<?php`, otherwise tinker prints the whole file as text.

## Presentation pass: hero, fact band, fact sheet, gallery

The page was "boring" mostly because it had **no imagery at all** (the `media` table had 0 rows
across the whole platform) and because every section was the same card in the same rhythm.

- **Hero**: photo is now an object, not a backdrop — a 4:3 plate in the right column with a
  cream date badge pinned inside its lower-left corner. The same photo is reused as a blurred
  `opacity-[0.20]` ambient wash behind the dark panel, plus the octagram lattice at 5%.
- **Fact band** (Tarikh / Masa / Tempat / Format) sits inside the hero above a `border-t`, which
  replaces the old one-line "date · time · venue" glance line. Grid class is computed from the
  row count so 1–4 facts never leave holes.
- **Photo fallback**: `$heroImageUrl` is built from *real media only* — deliberately **not**
  `Event::card_image_url`, which falls back to an institution logo or a stock placeholder and
  crops badly at 16:9. With no upload the slot shows a typographic date leaf instead, so the
  hero never reflows around a missing image.
- **Butiran** became a ruled fact sheet on the canvas (no card). Tried a 2-column grid first —
  it left an L-shaped hole in the last row whenever the row count was odd. One column, label
  left / value right, full-width rules, is the version that survives any count.
- **Gallery**: 1 image → full-width 16:9 plate; 2+ → 4:3 grid; 0 → section omitted entirely.
- Short descriptions are set as a serif lead line; the `.mi-dropcap` only applies above 320
  characters, because a drop cap on a one-line paragraph is decoration.

Hero grid needs **two breakpoints**: `lg` at 23rem / `xl` at 32rem for the photo column. A
single `lg: 32rem` squeezed the title into three lines at 1024px.

Generated the three demo photos with `codex exec --skip-git-repo-check` (built-in image
tool, ~1672x941 output). They are **placeholders** for the demo event
`22493052-…` / occurrence `01a13f3a-…` and should be replaced with real majlis photography.
